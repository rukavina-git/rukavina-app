# rukavina.app

Personal services and portfolio site for Ivan Karlo Rukavina (always the full name), a senior software engineer offering freelance
work, team augmentation and consulting.

## Goal

A qualified visitor understands who Karlo is and what he offers within five seconds, trusts the quality of
the work, and makes contact. Everything on the site serves that path.

Audiences, in priority order:

1. Engineering managers hiring contractors
2. Agencies that need extra senior hands
3. Startup founders and CTOs
4. Non-technical business owners who need an app or a website

The first three share one voice. The fourth gets its own path, written without jargon.

## Stack

- Astro (TypeScript, strict), deployed on Vercel from `main`
- Static pages; one on-demand route for the contact form (Vercel adapter)
- i18n with Astro routing: English at `/`, Croatian at `/hr/`
- Portfolio and services as Markdown content collections with Zod schemas
- Email through Resend

The site is not scaffolded yet. Add the commands below once it is, and keep them accurate.

```
npm run dev       # local dev server
npm run build     # production build, must pass before every commit
npm run check     # astro check (types, content schemas)
```

## Content rules

- Never add a claim, metric, client or testimonial that Karlo has not confirmed. Ask instead.
- Confirmed claims: 50,000+ users reached (one government app; keep wording general), 10+ projects shipped, Master's in Computer Science, reply within
  24 hours, free first consultation, based in Split, Croatia, working remotely.
- NDA work (government projects and others) is described by problem, scale and technology only: no client
  names, no screenshots, no identifying details.
- Public projects: GymBuddy, Adriava. An AI project and one more are planned; add them to the portfolio
  only when they exist.
- Services: Mobile development, AI integration, Architecture and code review, and a separate page for
  businesses. Never "Android" as a service name.
- No CV on the site, ever. No prices until Karlo decides on them.
- Tone: a senior professional a company would bring in and talk to. Not a sales site: no urgency, no hard
  selling, no marketing superlatives.
- Every user-facing string exists in both `en` and `hr` in the same change. Missing Croatian copy is marked
  with a `TODO(hr)` comment, never left out.
- Plain, specific language. No hype words, no filler.

## Design

Visual direction lives in `PRODUCT.md` and `DESIGN.md`, produced and maintained through the `impeccable`
skill. Read both before any UI work. Every page passes `/impeccable audit` and `/impeccable critique`
before it is considered done. Avoid template patterns: dark navy with violet accents, particle backgrounds,
pulsing status pills, centered hero plus stats row, fade-up motion on everything.

## Workflow

- Plans live in `docs/plans/<NN-name>/` as numbered step files. `/step` executes the next one.
- Decisions that change how the site sells go through `/council` and are recorded in `docs/decisions/`.
  Karlo makes the final call; the record is not a decision until his line is filled in.
- Run the `reviewer` agent on every change before committing.
- Versioning: `package.json` starts at `2.0.0`; tag `v2.0.0` at launch.
- Conventional commits (`feat:`, `fix:`, `chore:`, `docs:`). Small, focused commits.
- No "generated by" footers in commits, PRs or code. Co-author trailers in commits are fine.
