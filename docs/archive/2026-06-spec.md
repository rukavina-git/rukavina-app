## Animation System

Use **GSAP + ScrollTrigger** for all scroll-driven animations.
Use **pure CSS keyframes** for continuous/ambient animations (hero blobs).

### Setup (in a client component or layout)
```ts
import { gsap } from 'gsap'
import { ScrollTrigger } from 'gsap/ScrollTrigger'
gsap.registerPlugin(ScrollTrigger)
```

### Standard Scroll Reveal
```ts
gsap.from(element, {
  opacity: 0,
  y: 44,
  duration: 0.85,
  ease: 'power3.out',
  clearProps: 'all',  // ALWAYS include — prevents hover conflict
  scrollTrigger: { trigger: element, start: 'top 78%' }
})
```

### Grid Stagger
```ts
gsap.from('.card', {
  opacity: 0, y: 44, duration: 0.85,
  ease: 'power3.out', stagger: 0.1,
  clearProps: 'all',
  scrollTrigger: { trigger: '.grid', start: 'top 78%' }
})
```

### Hero Text Line Reveal
```ts
gsap.from('.hl-line > span', {
  yPercent: 110, duration: 1.05,
  ease: 'power4.out', stagger: 0.14,
  clearProps: 'transform'
})
```

### Hero Mesh Blobs (pure CSS)
4–5 absolutely positioned divs with `filter: blur(90px)` and radial-gradient backgrounds.
Animate with CSS `@keyframes` — slow drift/scale. Colors: accent (teal) and warm (rust).
No JS required. See `HeroBlobs` component.

### Rules
- Always `clearProps: 'all'` on scroll animations — prevents fill-mode conflicting with hover states
- Respect `prefers-reduced-motion` — wrap all GSAP init in a check
- Register ScrollTrigger once globally, not per component

## Page Structure

### / Home (`/[locale]/page.tsx`)

A teaser/hub page. Each section is shorter than on the inner pages.
Link every section CTA to the full page.

Sections in order:
1. **Hero** — full headline, subtext, two CTAs, mesh blobs bg
2. **Services teaser** — 4 cards, "See all services →" link to /services
3. **How It Works** — 3 steps (Discovery, Proposal, Build & deliver)
4. **Work teaser** — 2–3 project cards, "View all work →" link to /work
5. **About pull-quote** — short paragraph + "More about me →" link to /about
6. **Contact CTA** — headline + single button "Let's talk" → /contact

No FAQ on home. No full contact form on home.

### /services (`/[locale]/services/page.tsx`)

All 4 services in depth. Each service gets a full section, not just a card.
Structure designed so adding `/services/[slug]` sub-pages later requires minimal refactoring.
Store service data in `lib/data/services.ts`.

### /work (`/[locale]/work/page.tsx`)

Portfolio grid. All projects. Filter by type (All / Android / Web) — simple state, no URL params needed.
Data in `lib/data/projects.ts`.

### /work/[slug] (`/[locale]/work/[slug]/page.tsx`)

Individual project page. Generated from projects data.
Show: name, client, type, full description, tech tags, screenshots (placeholder), live link or NDA notice.
generateStaticParams from projects data.

### /about (`/[locale]/about/page.tsx`)

Full bio, skills cloud, profile card. LinkedIn link.

### /contact (`/[locale]/contact/page.tsx`)

Contact form (wired to Resend) + full FAQ accordion.

## Contact Form — Resend

### API Route (`/api/contact/route.ts`)
```ts
import { Resend } from 'resend'
const resend = new Resend(process.env.RESEND_API_KEY)

export async function POST(req: Request) {
  const { name, email, service, message } = await req.json()
  await resend.emails.send({
    from: 'rukavina.app <no-reply@rukavina.app>',
    to: process.env.CONTACT_TO_EMAIL!,
    subject: `New inquiry — ${service}`,
    html: `<p><b>${name}</b> (${email})</p><p>${message}</p>`
  })
  return Response.json({ ok: true })
}
```

### Form fields
- Name (text, required)
- Email (email, required)
- Service (select: Mobile Development / Web Development / Architecture Consulting / AI Integration / Other)
- Message (textarea, required)

No budget field.

## Important Notes for Claude Code

1. **Keep structure open** — avoid patterns that make refactoring painful.
   Data in `lib/data/`, content in `messages/`, components composable.

2. **Service sub-pages are coming** — `/services/[slug]` will be added later.
   The `/services` overview page should be built so extracting per-service content
   to sub-pages later is straightforward. Put service data in `lib/data/services.ts`
   from day one.

3. **No hardcoded content in components** — all user-facing strings go through
   next-intl translation keys. Even if HR translation is placeholder at first.

4. **Croatian translations** — if you don't have Croatian content, use English
   as placeholder in `hr.json` with a TODO comment. Do not fabricate Croatian text.

5. **GSAP + Tailwind** — don't fight each other. GSAP targets DOM elements,
   Tailwind handles static styles. Use `clearProps: 'all'` always.

6. **Resend domain** — assume `rukavina.app` is verified in Resend.
   `from` address should be `no-reply@rukavina.app`.

7. **Image placeholders** — use Next.js `<Image>` with placeholder props.
   No external image CDNs. Real images will be added manually later.

8. **Mobile responsive** — every component must be responsive.
   Tailwind breakpoints: `sm` (640) `md` (768) `lg` (1024) `xl` (1280).

9. **TypeScript strict** — no `any`, no implicit returns, no unchecked nulls.

10. **One task at a time** — when implementing, do one page or one component
    at a time. Confirm before moving to the next.
